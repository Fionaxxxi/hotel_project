# ADR-010：G1 来源接入与激活

日期：2026-10-26。状态：已实施。

完整包使用 multipart 上传 manifest.json 和五个 CSV，禁止服务器路径、压缩包和远端 URL。原始字节保存于服务端生成的 UUID 目录，元数据/摘要受租户隔离。包摘要按文件名排序计算，不依赖上传顺序；相同租户供应商的重复包复用批次。

G1 使用固定 v1 模板、单物业完整 snapshot；任何阻断错误均不激活。质量问题存于 import_batch.issues，规范化行与原始字段存于 staging_record.data，记录序号与 artifact 关联。未单独建设通用 processing_run/dq_issue 引擎；G2 进行版本化处理尝试及规模化报告扩展。

分区采用供应商+物业+完整实体/日期 scope，事务 advisory lock 覆盖首次分区和重叠检查；相同 scope 的来源序号严格上升，非相同且重叠日期范围显式拒绝。事实未变化时允许继承既有批准映射，但生成 system.mapping-reuse 决策并引用原批准记录；关键事实变动不继承。

G1 所需来源、映射、商品和任务结构集中于 002，命令幂等补充于 003，渠道独立编码补充于 004。实际分组不同于计划的建议文件分组，不改变业务边界。已执行迁移不修改，checksum 检查继续有效。

权衡：G1 有界读取完整小文件，最大单文件5 MiB/整包20 MiB/单类5000记录；不宣称十万行流式性能。G2 扩展 delta、重叠覆盖、坏行分区激活和大批处理。
