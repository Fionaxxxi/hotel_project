# ADR-027：基准暴露的队列问题与隔离复现

日期：2026-10-28。状态：实施决定，修复效果以最终复测为准。

早期混合实验出现真实超时。安全扫描从每次重复检查20个商品改为持久到期、短事务领取后再按源锁校验；不在持有listing锁时逆序等待源锁。保留派发前逐次安全检查。

分层测量进一步发现周期读取重复排队、旧读取阻塞新目标核验。修复为：周期/手工读取合并；新目标核验G3_VERIFY与发布共享前台机会，G3_RECON为后台周期读取；4:1公平机会、可借空闲、STOP始终优先。已停卖周期核验5分钟、其他通常1分钟，不延迟首次关闭确认。领取SQL仅添加实际需要的过滤条件，配合tenant/kind/resource/state/due索引，避免长期历史数据下的可空OR查询退化。旧重复读取保留CANCELLED及原因，不删除、不重发发布。

协议万格完整JSON压力与常规业务共享同一PostgreSQL时会相互竞争，因此分层基准单独执行，额外饱和实验单列失败。超时不从分母消失，修复后重新执行同预算。

本机复现使用两份新源码、两个npm离线安装/构建与两组三库；固定自然业务ID、业务时钟与字段，允许技术UUID不同，以实际业务payload hash对照。固定8006/8007仅在恢复库配置下可用，普通核心不接受该配置。它不等于另一台干净Windows；该项按用户确认暂待独立环境。

完整回归中的暂停竞态再次暴露：投递外盒中继先消耗不相关的审批通知，目标任务尚未获得G3_DELIVER作业。中继改为只消费其负责的g3.intent.created，独立inbox继续保护同一意图只调度一次；G2工作流消费者保留自己的通知消费，不以共享delivered_at替代多消费者确认。追加022索引支持事件类型领取；加入50条无关审批通知积压测试，并保留真实崩溃后inbox与作业原子性验证。

真实双Worker负载发现：外盒行本身未更新，LockRows取得行锁之前的NOT EXISTS快照不能作为消费所有权。inbox唯一插入改为ON CONFLICT DO NOTHING RETURNING id，只有真正插入成功者调度作业，竞争失败正常结束而非退出Worker。并发中继集成测试验证每事件只有一个inbox、每任务只有一个投递作业。20秒额外积压探针未达到的记录单独保留；正式完整链使用原先冻结的120秒预算，并继续断言先于100条旧读取完成，不将额外探针失败抹去。

2026-10-29隔夜最终检查发现单Worker因连接池PoolTimeout退出。分销循环现在只对PoolTimeout和OperationalError记录类型并退避后继续，保留原租约、request key与版本栅栏，不将失败调用改为成功。未知编程/约束错误仍直接暴露。加入同一Worker故障后继续执行且退出时关闭连接池的回归；60分钟原始测量属于该补丁前版本，最终补丁后完整回归与正常进程检查另存证据。

随后306项回归出现重新开售在既有25秒检查窗口不收敛。保留305通过/1失败全量报告，并以函数及SQL模板耗时定位：外盒delivered_at回补及受限任务集合查询在历史数据下累计约30.5秒。两处补齐显式tenant条件，JOIN同时包含tenant/id；外盒只回补本消费者负责的g3.intent.created。继续使用现有索引，无迁移、无清历史、无放宽断言。相同专项14.92秒通过，修复前偶然通过的40.34秒结果也保留，最终仍要求完整回归通过。
