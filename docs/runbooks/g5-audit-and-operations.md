# G5 风险与只读审计

“风险与审计”页只查询当前租户。ready/running/retry、人工WAIT、UNKNOWN、死信和过期租约分别统计；可执行队列年龄以真实数据库时间计算，STOP调度的人为提前优先级不会被误算为一小时前就已积压。全局数据库连接池信息仅进入本机运维日志，不经租户指标接口返回。

告警按租户和有限风险类别聚合，完整统计数量，最多附10个对象样本。不能截取最早100个对象后就声称风险全集已采集。OPEN表示风险存在，ACKNOWLEDGED表示有操作者接手，RESOLVED只能由一次成功的完整采集确认。采集失败回滚，不把旧告警清空。来源TTL使用显式业务时钟，其余队列、心跳、令牌和备份年龄使用真实时间。

默认告警包括：停卖5分钟未确认、UNKNOWN1分钟、外盒1分钟滞后、租约过期、Worker30秒无心跳、死信、持续429、来源24小时过期、备份24小时陈旧。阈值不是生产SLA。长事务或繁忙Worker也可能触发心跳过期，需要结合队列和进程核查，不能只按心跳文字判定进程死亡。

## 队列与处置

派发前仍执行原G3权限、快照、策略epoch、source、额度及stop fence校验。新目标的首次核验使用 `G3_VERIFY`，和发布一起获得前台执行机会；后台周期对账使用 `G3_RECON`。正常按4:1机会分配、无任务时立即借用另一队列，紧急STOP始终优先。两者都是原版本/租约保护下的读取与核验，不表示发布许可放宽。

同商品已有READY/RETRY_WAIT/RUNNING读取任务时，周期和手工读取会合并。新目标需要核验时提升尚未执行的读取任务，不重复排队。已停卖商品周期核验为5分钟，其他通常1分钟；实际关闭后的首次确认立即执行，手工查询可随时请求。调度周期不保证整个大系统在该周期内全部扫描完成。

UNKNOWN继续查询原operation/key；429核对账号级配额；租约过期交给有fence的重新领取；MANUAL/死信须按实际版本和理由重开有限预算。告警接手不会重试发布，后台采集失败也不会阻断紧急关闭。

## 回放与导出

入口支持listing、G3 snapshot、G4 run、batch的完整UUID。节点包含具体版本、actor、时间、状态、hash及真实外键关系。payload能够复算时标记VALID或MISMATCH；不能复算的对象显示NOT_APPLICABLE，不冒称已验证。

每次图查询有节点、字节与时间上限，达到上限显示truncated且complete=false。复杂长期listing可改用更具体的snapshot或batch入口；不完整导出不能被标记为完整审计。旧记录未保存关联ID时明确缺失，不按时间相近臆造因果。

原始位置以 `processing_record.locator` 为准：CSV是含表头约定的逻辑记录号，XLSX是sheet/row，JSON是record/path。staging记录属于投影，不是原文件物理行号。多行CSV字段不能把逻辑记录号直接叫“文件行号”。原件仍通过受权下载，保留原字节。

审计员和本租户管理员可导出JSON脱敏包；普通运营不能通过该导出取得额外审计权限。manifest含版本、完整性、字节数和SHA-256；离线工具可检查内容改动，但同包hash不构成第三方签名。导出行为另记审计，回放不会调用AI、编译、批准或发布。

CSV质量报告使用安全展示转义，包含前置Unicode空白、BOM和C0控制符的危险公式前缀也会加字面前缀；这不修改原始文件。

## 关联与日志

服务端生成HTTP trace_id；解析job保留correlation及cause，G4沿原解析运行继续关联到G3外盒、领取尝试和模拟器响应。版本关系仍是审计因果的主要依据。日志中的全局资源统计仅供本机运维，不能作为租户公开指标或当成不可变审计本身。

排查顺序：确定当前租户/对象 → 看确切版本和最近尝试 → 判断人工等待/队列/UNKNOWN/停卖 → 按既有业务命令处理 → 重新读实际结果。禁止通过修改hash、直接把状态改VERIFIED、删旧收据或关闭审计来让页面变绿。
