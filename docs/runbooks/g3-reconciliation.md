# G3 对账与安全修复

desired=授权目标，applied=有落地证据的目标，observed=实际远端读取版本/时点。历史任务VERIFIED不保证现在仍一致。

1. 在listing排队对账，或等待60秒周期；实际HTTP读取在事务外，落盘前核对当前intent，目标变动时记STALE_OBSERVATION。
2. UNKNOWN表示读失败/不完整；不要把它当远端缺失。MISSING是有效读取证实目标格不存在；DRIFT是数量/价格/政策等不同；REMOTE_AHEAD人工调查。
3. 普通漂移只有原审批明确allow_repair、期限/来源/映射/额度/能力仍有效且当前不是STOP目标时才能原样重放。原操作key只返回历史receipt，所以新修复使用新delivery序号/key，并保留同一业务hash。
4. 原版本每目标最多3次修复，超限或权限不足需人工处置。永久cell拒绝保持BLOCKED，不能用修复掩盖。临时拒绝仅处理未完成格。
5. 观察到更高实际库存时，保守提高曝光保留；超过当前池日容量时记CAPACITY_DEFICIT、冻结新增额度并由受限安全actor关闭受影响日期。只有真实核验降低后才释放。
6. 对账恢复后看新observation逐格相符，而非只看发送receipt或修复job成功。

默认一次有界完整JSON读取，complete标记用于不完整观察测试。当前没有真实远端分页/读版本令牌，接入此类协议时必须另做一致性处理。

预算、配额、人工授权和观察延迟都计入实际收敛时间。总设计“两周期”只在有效授权、模拟器可用、无配额阻塞时作为待测目标，不把单次手工成功外推为生产SLA。
