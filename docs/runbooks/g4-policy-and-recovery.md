# G4 策略、等待与恢复

1. 在G3完成人工映射、接管CLEAR/CLOSED、初始安全额度和两个NONREF人工批准快照。快照仍有效且属于同一来源/额度。
2. 管理员在流程页选定两个基准，填写逐次/累计相对限额与绝对限额，分别确认自动激活和发布授权，创建并提交策略。
3. 切换独立审核账号，核对完整范围、固定基准、buffer与A/B额度后批准。管理员启用并创建来源订阅。
4. 后续同范围合格上传由后台接续。查看WAIT_SCOPE/QUALITY/MAPPING/ALLOCATION/APPROVAL，进入相应现有业务界面处理明确对象；不能用通用resume跳过检查。
5. 价格越界后，每个新快照保留REVIEW原因。审核人可针对确切快照独立批准；这不会改变原策略固定基准，也不会使下一次异常自动通过。
6. 暂停或撤销策略使旧机器授权失效。待派发任务可能进入G3人工处置，先恢复/重新判定当前授权，再按G3有限预算手册处理；不要盲目反复发送。查询和关闭继续允许。
7. 需要改变授权内容时创建新的独立批准策略，停用旧策略后启用新策略；通过`POST /v4/subscriptions/{id}/policy`携带policy_id、expected_version和reason重绑。未发出的等待流程清除旧快照引用重编译；历史计划和决定保留。首版换版操作接口可用，页面先提供常规策略操作。
8. 策略暂停不是停卖。需要止损，进入双渠道页核对当前版本和范围，分别提交关闭，实际两边STOPPED才完成。自动流程不能解除停售；恢复开售仍走G3新快照/新独立人工审批/显式reopen。

源容量不足时保持WAIT_ALLOCATION，必要时由G3安全关闭；不要减buffer或将尚未确认降低的曝光挪给另一渠道。新来源使旧run过时则STALE，按最新run处理。

故障恢复证据：G4实际退出91发生在自动事务提交前，92发生在提交后；重跑协调器分别重新推进或复用已存在G3计划。消费者inbox、步骤和原计划唯一键防重复。正常服务不提供退出注入API。
