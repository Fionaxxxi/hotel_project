# G3 停卖、超时告警与重新开售

暂停不撤回在途HTTP；取消只支持确未发送的首次计划；停卖是新的业务关闭目标。所有动作保留审计。

## 手工关闭

租户管理员选择listing及受影响日期，填写原因，提交expected version和Idempotency-Key。服务端创建更高desired/delivery revision及stop epoch，旧未发送售卖/repair替代为SUPERSEDED；在途任务仍查询。

关闭按共享池日期覆盖依赖计划，读到数量0及sellable=false后才确认。全范围关闭为STOPPED；部分日期关闭需查看目标范围/逐格观察，不得把剩余仍售日期称为全关闭。A已关闭B未知时分别展示，不能整体报成功。

## 自动安全关闭

system.safety仅对确定的来源/映射/快照失效、明确关闭输入，以及已观察/已保留曝光超过容量等风险减少曝光。普通坏行不推断删除；旧额度版本本身不当作来源撤销。关闭使用最后已知渠道商品，不要求失效来源能重新生成正常售卖快照。

5分钟未确认产生STOP_UNCONFIRMED_OVER_5_MINUTES持久告警；不得伪造STOPPED或删除任务。先查账号限流/认证、原operation和实际读取，必要时管理员按恢复手册有限处置。普通业务积压不会获得高于关闭任务的调度优先级，但仍不能绕过硬配额。

## 新开售

确认关闭完成后，核对新鲜来源、映射和剩余额度，创建并独立批准新的G3快照，显式reopen提交新计划。旧快照、普通账号恢复、对账和repair均不得恢复售卖。计划CAS冲突需刷新后重新核对，不能强行跳过。

## 旧SIM-A协议迁移

先接管并读旧listing，EXPOSED由管理员执行close-legacy。旧关闭revision在HTTP前持久保留，之后任何G1编译都以已保留/观察版本接续；低版本迟到请求仍由旧SIM-A远端拒绝。只有实际确认旧曝光下降/关闭才能给SIM-B新增额度。UNKNOWN保持阻断，不能把数据库字段改成CLEAR放行。
