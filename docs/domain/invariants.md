# 领域不变量与走读 v1

1. 酒店、房型和价格计划不能混同。同名异店不合并，同店 King/Twin 不等价，同房型可退/不可退不等价。
2. 两个计划共用 POOL-1 的四间，事实仍然是四间。不同来源池未知共享关系时拒绝求和。
3. 房态日为酒店本地 DATE；事件为带时区时间。入住 `[2027-01-10,2027-01-13)` 占用 10、11、12 日三晚。
4. NUMERIC(18,4) 与 Decimal 保存计算金额，USD 按两位 ROUND_HALF_UP 输出；拒绝非有限数、非正价格和越界值。不自动补税。
5. MVP 仅一间、两成人、无儿童。取消政策保留原文、结构化阶梯和计算基数；未知时区或金额基数阻断出售。
6. 租户由可信身份和有效成员关系确定，文件 manifest 不允许 tenant_id，客户端选择租户不能授予成员资格。
7. 所有跨租户业务引用使用复合外键；current_version 必须属于同一实体。历史版本及审计对应用角色追加只读。
8. delta 缺行表示不变；snapshot 缺行只有在完整且合法的 scope 内才可解释为关闭。坏行不能被当作删除。
9. 发布快照不可变。任何业务输入变动都需新快照和新审批决策，不复用旧 hash 审批。

## 四组走读结论

| 案例 | 唯一预期结论 | 当前证据 |
| --- | --- | --- |
| 两计划共享四间 | 返回四间，不返回八间 | F00 中两计划指向同一 pool；纯函数测试 |
| 三晚入住 | 只包含入住日至退房日前一天 | stay_dates 测试 |
| 同名异店 | 名称不能成为全局唯一键 | T-A/T-B 故意同名；不同 UUID 与租户 |
| 同房不同取消 | 分别保留 FLEX 与 NONREF 计划及版本 | 种子与文件中的独立政策 |

这些走读验证口径，不表示映射算法、报价编译器或库存激活已经实现。
