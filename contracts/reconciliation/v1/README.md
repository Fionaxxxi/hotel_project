# 三方对账与关闭契约

desired是当前授权目标；applied是已确认落地的业务版本；observed是实际读取的远端版本和时点。历史成功与当前漂移同时成立，不改写历史回执。

分类：CONSISTENT、PENDING、MISSING、DRIFT、UNKNOWN、REMOTE_AHEAD、STALE_OBSERVATION。超时/认证/完整性失败为UNKNOWN，保留先前可信观察；全部目标格不见为MISSING，部分内容差异逐格列DRIFT。读取期间本地目标变动则本次观察过时，不能认证新目标。

每60秒周期及按需任务使用持久next_due_at和SKIP LOCKED；每个真实due时点有唯一job逻辑键。最后chunk完成重新安排核验，不按过粗时间桶把这次信号吃掉。

原样修复必须：当前desired/审批/依赖/额度/能力仍有效，批准者明确allow_repair，且无当前STOP目标；每业务版本最多3次。新修复使用新delivery revision/key，旧成功key只会回放receipt，不能用来修复漂移。临时拒绝的原任务未完成格可继续有限重试，仍重验授权；永久拒绝不会被自动当普通漂移抹掉。

关闭：管理员紧急命令或受限system.safety触发；明确stop、来源/映射/快照失效等确定安全条件生成减少曝光的目标。ALLOCATION_STALE本身不当作来源撤回。关闭依据最后已知商品和渠道范围，不要求失效来源能重新通过售卖编译。数量0/不可售均核验后才STOPPED；一边未知不算整体完成。

stop epoch和更高远端版本压制旧售卖/旧repair；恢复必须关闭后新创建并独立批准的快照、有效来源/额度，以及显式reopen命令。普通恢复账号/派发不会解除关闭。关闭超5分钟未确认产生持久告警，读不到不能假装已关闭。

首版远端读取为一次有界完整JSON，complete故障标记用于不完整读负测；不宣称已有真实分页/读版本令牌实现。复杂远端分页协议需后续适配，不能把计划描述当作现有能力。
